# Производство ассетов через Pixelmon

## Звук этапа 6

Звук синтезируется Web Audio из оригинальных числовых рецептов `src/data/audio.ts`; внешние записи, модели, семплы и новые PNG не используются. Рецепты задают waveform, начальную/конечную частоту, длительность и огибающую громкости для фонаря, игл, колокола, опыта, урона, уровня и исхода. Фон — три тихих синусоидальных тона 110/164.81/220 Hz. Источник — код проекта; seed не применяется, случайных генераторов нет. Параметры сохраняются непосредственно в рецепте; реализация — `src/systems/gameAudio.ts`, зависимости прежние, исполнение — браузерный Web Audio. Изменение рецепта требует повторной проверки сигнала/громкости в браузере.

В stage-6 browser smoke проверены state=locked до пользовательского действия, реальный ненулевой RMS после включения, нулевой RMS при громкости 0, остановка фона при паузе и отсутствие роста каналов после рестартов. Это проверка цифрового сигнала, а не субъективная оценка звучания физических колонок. Запись интерфейса WebM не содержит отдельной записи системного аудио. Аудио не включено в манифест графических атласов: готовых аудиофайлов для загрузки нет.

Проверенные первичные API: [AudioContext.resume](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/resume), [Web Audio best practices](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices). Создание и resume выполняются внутри пользовательского события; громкость управляется через GainNode, закончившиеся узлы отключаются.

## Порядок производства

1. Прочитать ART_DIRECTION, выбрать один asset ID и записать задание: размер, силуэт, направление и состояние.
2. Получить несколько базовых вариантов маленькой серией, выбрать согласованный вид. `--fast` допустим для черновиков; полное качество проверять отдельно, оно может отличаться даже при том же seed.
3. Сохранить точный положительный/отрицательный промпт, seed, аргументы и версию Pixelmon. Не считать один seed гарантией идентичности при другом окружении.
4. Подготовить изображения направлений и реальные кадры движения на основе выбранного вида. Pixelmon используется для базы; покадровую правку делать в доступном пиксельном редакторе или инструменте обработки изображений. Не заменять циклы генерацией несвязанных картинок.
5. Выровнять кадры на фиксированном холсте, сохранить прозрачность и палитру, собрать атлас PNG + JSON без trimming/rotation.
6. Просмотреть в тестовой сцене Phaser, записать движение и стыки; только после проверки поставить approved и подключить runtime-манифест.
7. После принятия героя, ползуна и земли перейти к остальному контенту.

Экспериментальный `--animate` Pixelmon предназначен для небольших жестов/свечения; он не является производственным решением для ходьбы и восьми направлений. `--tile` помогает повторению одной текстуры, но не создаёт готовый 47-тайловый переход между материалами.

## Метаданные производства

Для каждого принятого ассета создать JSON рядом с исходниками. Минимальные поля: `assetId`, `sourceKind`, `prompt`, `negativePrompt` (null = настройка инструмента по умолчанию), `seed`, `arguments`, `toolCommit`, `modelIdentifiers`, `generatedAt`, `sourceFiles`, `edits`, `licenseNotes`, `reviewStatus`, `evidence`.

Если используется отрицательный промпт, хранить его фактический текст. Записывать модели и их версии/хеши, если доступны; неизвестные значения явно обозначать, не придумывать. Для доработанных кадров `edits` описывает автора/инструмент, операции и исходную базу. Отдельный рендер другого направления получает отдельные параметры. В provenance разрешены пути относительно проекта; личные абсолютные пути не нужны.

Runtime-манифест создан в `public/assets/manifest.json`; ниже приведён сокращённый пример его формы:

```json
{
  "version": 1,
  "assets": [{
    "id": "hero_lantern_keeper",
    "type": "atlas",
    "status": "approved",
    "texture": "assets/hero/lantern-keeper.png",
    "atlas": "assets/hero/lantern-keeper.json",
    "frameSize": {"width": 64, "height": 64},
    "origin": {"x": 0.5, "y": 0.875},
    "directions": ["n", "ne", "e", "se", "s", "sw", "w", "nw"],
    "clips": [{
      "state": "walk", "direction": "s",
      "frames": ["hero/walk/s/00", "hero/walk/s/01", "hero/walk/s/02", "hero/walk/s/03", "hero/walk/s/04", "hero/walk/s/05"],
      "fps": 10, "repeat": -1
    }],
    "provenance": "assets-source/approved/hero/metadata.json"
  }]
}
```

Пример показывает один клип, а принятый герой обязан содержать все состояния и направления из ART_DIRECTION. `provenance` — ссылка для разработки, не запрос браузера; metadata остаётся вне `public/`. Runtime URL разрешать относительно Vite base URL, а не файловой системы. Плейсхолдеры используют `status: placeholder` и никогда не выдаются за approved.

Имена кадров: `<entity>/<state>/<direction>/<двухзначный индекс>`. У симметричного эффекта направление `none`; это не разрешено для героя. Переходы земли дополнительно описывают пару материалов и таблицу нормализованная маска → имя кадра.

## Реализованный процесс этапа 1

`tools/generate-bases.py` запускает только небольшой набор из пяти базовых исследований (герой, ползун и три материала). Он сохраняет полезные исходники в `assets-source/candidates/`; сырые попытки остаются в игнорируемом `assets-source/drafts/`. У героя принят seed 1102; seed 1101 выдал лист персонажей и отклонён. Базовый рендер ползуна был слишком высоким для игрового силуэта, поэтому при доработке тело перерисовано низким и широким.

`tools/build-art.py` делает полную пиксельную перерисовку по базовым исследованиям, отдельно конструирует направления и положения конечностей, собирает атласы без trimming/rotation. Генеративная анимация не используется. Трава и земля имеют редкие кластеры, брусчатка — маленькие округлённые камни; края и маски подготовлены отдельно. Генерация и сборка запускаются в Ubuntu WSL из корня игры с существующим Python ComfyUI, содержащим Pillow 12.3.0:

```bash
~/ComfyUI/.venv/bin/python tools/generate-bases.py
~/ComfyUI/.venv/bin/python tools/build-art.py
```

Эти локальные команды не являются зависимостью браузера. `npm ci`, `npm run dev` и `npm run build` используют уже сохранённые атласы и не запускают GPU.

У принятой версии метаданные и базовый PNG находятся в `assets-source/approved/<assetId>/`. Метаданные включают промпты, seed, параметры, Pixelmon 1.9.0 / `355bd0b`, локальные SHA256 моделей, операции перерисовки и доказательства. Идентичность локальных моделей относительно upstream определяется по именам файлов и отдельно не подтверждена сравнением хешей. Карточки [SDXL](https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0) и [Pixel Art XL](https://huggingface.co/nerijs/pixel-art-xl) указывают соответствующие Open RAIL-лицензии; веса в проект не копируются.

`tools/check-assets.mjs` проверяет URL, provenance, палитру ENDESGA-32, размеры, бинарную прозрачность, кадры, состояния, направления и 47 масок. Флаг `--require-approved` дополнительно исключает placeholder. `tools/check-tile-seams.mjs` сверяет покрытие краёв соседних переходов на фиксированной случайной сетке. Проверка покрытия не заменяет визуальную проверку текстур.

Этап 2 повторно использует принятые атласы без изменения PNG/JSON и их provenance. Импульс фонаря, искры опыта и кольца подбора рисуются кодом `RunScene.renderWorld` как простые формы ENDESGA-32 (`feae34`, `fee761`), без новых растровых ассетов и генерации. Источник — собственный код проекта; у импульса кольцо расширяется и гаснет за 0,3 с, искра качается по фазе игрового времени и получает кольцо при подборе. Это эффекты оружия/подбора, а ходьба существ продолжает использовать настоящие кадры. Пауза и выбор улучшения замораживают эффекты вместе с миром. Скриншоты и запись хранятся в `docs/evidence/stage-2/`.

Приёмка привязана к SHA256 PNG, JSON атласа и рецепта в `docs/evidence/stage-1/art-review.json`. После изменения рецепта или кадров сборщик возвращает соответствующие ассеты в placeholder до новой проверки. `tools/record-art-review.mjs --accept` записывает решение **после** просмотра PNG и WebM и успешных проверок; он не заменяет визуальную приёмку. Это локальная проверка агентом, а не заявление о приёмке пользователем.

## Окружение этапа 3

`tools/generate-environment.py` запускает один базовый рендер фонаря Pixelmon, seed 2401, 64×64, ENDESGA-32, 25 steps; повторный запуск использует сохранённую базу. Фактические аргументы, английские промпты, commit `355bd0b`, версия 1.9.0 и повторно измеренные SHA256 моделей сохранены в metadata. Исходный рендер имел несколько лишних конструкций фонарей, поэтому используется как исследование формы; runtime полностью перерисован. Растения и лужи опираются на принятые исследования земли, скамья/корни/фрагмент оранжереи созданы тем же пиксельным рецептом. Лицензии моделей повторно сверены с карточками [SDXL](https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0) и [Pixel Art XL](https://huggingface.co/nerijs/pixel-art-xl); идентичность локальных весов upstream по-прежнему не утверждается.

`tools/build-environment.py` собирает отдельный атлас `environment`: по четыре настоящих кадра plant/water/lantern и по одному статичному roots/bench/glass, всего 15 кадров 64×64, опора `(0.5, 0.875)`. Изменяются положения листьев, пиксельные полосы воды и контур огня; вращение/масштабирование одного кадра не применяются. Направление `none` используется только для симметричных деталей окружения, герои сохраняют прежние направления. Генераторы запускаются явно в WSL, как этап 1:

```bash
~/ComfyUI/.venv/bin/python tools/generate-environment.py
~/ComfyUI/.venv/bin/python tools/build-environment.py
```

Сборка сохраняет пять принятых атласов этапа 1. Новый атлас сначала placeholder, после просмотра кадров при 1×/2×, WebM и браузерных проверок `node tools/record-environment-review.mjs --accept` записывает точные SHA256 PNG/JSON/рецепта; повторная сборка применяет approved. Проверка ассетов сверяет эти хеши и четыре различающихся изображения каждого анимированного клипа. Любое изменение рецепта/PNG/JSON требует новой приёмки. Исходники и журнал Pixelmon сохранены в `assets-source/approved/environment/`, доказательства — в `docs/evidence/stage-3/`. Приёмка выполнена агентом, приёмка пользователем не заявляется. Браузер использует готовые файлы и не обращается к WSL/GPU.

## Контент этапа 4

`tools/generate-content.py` запускает шесть одиночных исследований: пять новых врагов (seeds 1202–1206, 64×64) и латунный предмет (3101, 32×32). Установленный CLI проверен перед запуском: Pixelmon 1.9.0 / commit 355bd0b, SDXL и Pixel Art XL. Фактический вывод, английский положительный/отрицательный промпт, аргументы, время и повторно измеренные SHA256 двух локальных моделей сохранены у каждого исследования. Не использованы новые модели, steering/control или генеративная анимация. Наличие базы позволяет продолжить прерванное производство без повторной генерации.

Исследования оказались неоднородными: бродяга слишком узкий, рой рассыпан, предмет плохо читается. Они служат материалом/силуэтным исследованием, не готовыми runtime-спрайтами. `tools/build-content.py` полностью перерисовывает тела, ноги, руки, крылья, отдельные стороны и разрушение существ. Четыре стороны направленных врагов собраны отдельно; рой имеет записанную радиальную симметрию. Move/hit/death содержат 4/2/4 кадра, prepare/attack специальных врагов — по четыре. Неподвижный холст 64×64 и опора y=56 сохранены. Кадры не получены масштабированием/поворотом одного изображения.

Добавлены семь атласов: пять врагов (266 кадров), `content_icons` (13 авторских иконок 32×32, включая бонусы) и `content_fx` (60 кадров 32×32: игла, живой мотылёк, колокол, вражеский снаряд, воск, магнит; движение/появление/попадание 4/3/3). Иконки используют исследование латунного предмета как материал, конкретные формы разработаны кодом. FX используют исследования роя и принятый язык янтарного огня; происхождение и доработка описаны в metadata. Шесть прежних атласов не пересобираются.

```bash
~/ComfyUI/.venv/bin/python tools/generate-content.py
~/ComfyUI/.venv/bin/python tools/build-content.py
```

После просмотра кадров 1×/2× и записей, успешных asset/browser-проверок `node tools/record-content-review.mjs --accept` сохраняет точные SHA256 рецепта и всех семи PNG/JSON. Повторный запуск только сборщика применяет approved и сохраняет исходники/metadata в `assets-source/approved/<id>/`. Изменение любого хеша возвращает соответствующий ассет в placeholder. `check-assets.mjs` дополнительно проверяет разные пиксели каждого кадра, кардинальные клипы, симметрию роя и хеши приёмки. Решение агента не означает приёмку пользователем.

Браузерные сценарии `tools/browser-stage4-*.cjs` запускаются через Playwright CLI `run-code --filename`; это файлы функций, не самостоятельные Node-программы. Для записи явно задавать `video-start <file.webm> --size 1360x1120`; размер viewport сам по себе не меняет размер WebM. Доказательства и условия — в [протоколе этапа 4](evidence/stage-4/REPORT.md). Runtime загружает готовые относительные URL и не использует локальные пути/модели.

## Босс этапа 5

`tools/generate-boss.py` запускает одно исследование Сердца оранжереи в установленном Pixelmon, seed 1301, 128×128, ENDESGA-32. Сохранены английский промпт, отрицательный промпт, фактические аргументы, Pixelmon 1.9.0 / commit 355bd0b, время и локальные SHA256 SDXL/Pixel Art XL. Рендер включал фон оранжереи и не подходит как готовый спрайт; он используется только для изучения воска, корней и латунного каркаса. Идентичность локальных моделей upstream не заявляется.

`tools/build-boss.py` делает полную пиксельную перерисовку на неподвижном холсте 128×128 с опорой (0.5, 0.875): idle/move по 4 кадра, отдельные prepare_thorns/attack_thorns и prepare_summon/attack_summon по 4, hit 2, death 8, всего 34. У корней отдельные суставы и фазы шага; раскалывается ядро, распадается каркас. Существо сохраняет фронтальную конструкцию без поворота; для этого босса направление none явно записано в provenance. Частота подготовки — 4/1,2 и 4/1,4 FPS, атаки 8 FPS: рисунок согласован с боевыми сроками. Прежние 13 атласов не пересобираются.

```bash
~/ComfyUI/.venv/bin/python tools/generate-boss.py
~/ComfyUI/.venv/bin/python tools/build-boss.py
```

Кольцевое предупреждение, движущийся обод шипов и кресты мест призыва — простые фигуры ENDESGA-32, рисуемые кодом RunScene; они не заменяют живую анимацию босса. После просмотра PNG 1×/2×, записей атак/смерти и успешного настоящего полного забега `node tools/record-boss-review.mjs --accept` фиксирует SHA256 рецепта/PNG/JSON. Повторная сборка применяет approved; изменение хеша снова требует приёмки. `check-assets.mjs` проверяет 128px, разные пиксели каждого кадра, все восемь клипов и хеши решения. Доказательства — `docs/evidence/stage-5/`, исходник и metadata — `assets-source/approved/greenhouse_heart/`. Приёмка агентом не означает принятия пользователем.

Браузерный полный забег проходит сегментами по 50 секунд через `tools/run-stage5.ps1`, каждое движение/улучшение выполняется обычным UI. Сегменты разделены явной паузой и не ускоряют часы. `npx --offline --package @playwright/cli` использует уже установленный CLI, без обращения к недоступному npm-зеркалу. Итог собирается `tools/collect-stage5-run.mjs`; `prototype_complete` мастерской не считается победой полного режима.
